# Release v0.1.0

Date: 2026-11-19
Branch: `claude/flood-simulator`

## Summary

First working build of Waterflow: a browser dam-failure flood simulator that uses public
elevation data, solves a published 2D hydraulic model on the GPU, and renders the result
as a place you can fly around.

It answers the question the project was started for: how much water goes downstream when a
dam fails, how deep it gets, how wide it spreads, how fast it moves and when it arrives,
reported at measured increments down the valley.

## Changes

See `CHANGELOG.md` for the full list. The parts worth knowing about:

**The breach is terrain, not a boundary condition.** Rather than computing an outflow
hydrograph and injecting it, the dam is real ground and the breach is that ground being
cut away over time. Water leaves because the solver routes it out. Reservoir drawdown,
outflow and downstream flooding are therefore one mass-conserving calculation instead of
three that can quietly disagree. It also means the dam-building tool and the breach
mechanism are the same code, and that the "percentage of a dam failure" control from the
original brief is a physically meaningful thing rather than a scaling factor.

**Every coefficient is sourced.** `docs/hydraulics.md` lists every equation with its
citation, the units of every variable, and the range of data it was fitted to. Where a
published value could not be confirmed in SI units, it was left out and recorded as an
open question rather than guessed. That is why the hydrograph's reference line is a weir
calculation that can be derived from first principles rather than Froehlich's peak-outflow
regression, whose storage coefficient is published in acre-feet.

**Results carry their assumptions.** The CSV header records the location, grid, cell size,
roughness, dam geometry, reservoir volume, breach settings and simulated duration, along
with the limitations notice. A results file that leaves without its caveats is how an
estimate gets mistaken for a finding.

**Movie mode.** A raft drifts on the actual velocity field, so where it goes is where the
water goes, and the camera can chase it, ride it, orbit it or hold on a tagged spot.

## Fixed bugs

Three defects were found by the browser verification harness and fixed before release.
All three produced plausible-looking output, which is what makes them worth recording.

1. **The reservoir filled the wrong side of the dam.** The pool was seeded on whichever
   side of the dam axis was lower. In a river valley the lower side is downstream, so the
   "reservoir" flooded the valley below the dam, grew to cover 70 percent of the loaded
   area and ran off the edge of the domain. Every arrival time came back as zero. Now the
   upstream side is found by following steepest descent from the point where the valley
   floor crosses the dam axis, which is drainage rather than elevation. Regression tests
   in `tests/dam.test.js`.

2. **The terrain collapsed into a ribbon.** Both vertex shaders wrote the elevation into
   `position.z`. Because the plane's rotation into the ground plane is baked into the
   geometry on the CPU, `position.z` holds the north-south coordinate and `position.y` is
   the free one. The displacement destroyed the north-south layout, so the whole world
   rendered as a thin diagonal band. Fixed by displacing `position.y`.

3. **The water surface was covered in a bright diamond lattice.** The macro surface normal
   was built from nearest-sampled bed and flux textures, which made it piecewise constant
   over each cell; at a specular exponent in the hundreds that became a grid of hard
   highlights. The solver state must stay nearest-sampled so the physics and the readbacks
   see cell values, so the fix interpolates in the fragment shader only, after the physics
   has been computed and recorded.

Also fixed: the default dam crest was taken from the highest ground along the axis, which
produced absurd impoundments when an abutment was dragged up a valley wall; it now comes
from the lower abutment, since a dam built above that is simply flanked by the water.
Fog density was fixed rather than scaled to the domain, washing a 24 km view into flat
grey. Procedural water detail now fades below one pixel instead of aliasing. A camera
following a raft that leaves the loaded area now hands control back instead of staring at
empty sky.

## Known issues

Carried from `CHANGELOG.md`:

- Elevation resolution roughly 10 m in the United States, coarser elsewhere.
- Single domain-wide Manning's n.
- Near-field results flagged as indicative.
- Small arrival-time inversions between stations with overlapping cross-sections.
- No scenario save and reload.
- Water reflects the sky but not the terrain.

## Upgrade steps

First release. Nothing to upgrade from.

```bash
npm install
npm run build
```

For a Docker deployment:

```bash
cp .env.example .env
docker compose up -d --build
```
