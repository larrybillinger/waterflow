# Release v0.3.0 — Advanced Hydraulic Studio integration

## Summary

Adds Claude's independently developed GPU-based dam-failure application inside Waterflow as a second mode under the same site.

## Changes

- New GPU Studio: reservoir-stage/volume setup, two-point embankment dam, published breach parameter estimation, progressively eroded breach, GPU depth/flux computation, 3D animated water mesh, D8 flood-path stations, flow depth/velocity/arrival metrics and hydrographs.
- Additional terrain edit brushes, undo and cinematic drone/raft views in Studio.
- Bidirectional links between the Classic 3D Lab and GPU Studio.
- Docker builds the Studio Vite bundle and FastAPI mounts it at /studio/.
- GitHub CI checks both implementations independently.
- Synthetic terrain is visibly labeled for the entire Studio session.

## Fixed bugs

No unrelated Classic behavior was intentionally changed.

## Known issues

- Separate engines and transient scenario states. No automatic parameter synchronization or imports.
- Studio synthetic fallback is NOT real geography; external tile access and browser WebGL2 features still require deployment testing.
- No engineering calibration against recorded floods or independent reference simulations.
- Combined Python deployment does not provide the optional Express tile proxy from Studio.

## Upgrade steps

Run docker compose up -d --build and open /studio/. Local Python development additionally requires cd studio && npm ci && npm run build; restart Python after the build.

## Rollback notes

Revert to v0.2.0, which used only Classic, without migrations or database changes. Both modes are transient and do not store scenarios on disk.

## Automated verification

GitHub Actions jobs for Classic Python/Node tests, Studio lint/unit/build, and a combined Docker HTTP smoke test have passed. Real Chrome/WebGL2 visual testing and hydraulic field calibration remain outstanding.
