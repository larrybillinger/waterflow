# Open questions

- Which real dams/valleys and catchment scales matter most?
- Should a later version use actual reservoir storage-stage curves or user-defined synthetic pools?
- What is the authoritative local DEM resolution and vertical datum for each region?
- What server/GPU deployment targets and expected concurrent users?
- What validation evidence and approved hydraulic reference models are needed for any use beyond experimentation?

- Should future v0.3 include an actual downloadable WebM/MP4, and would saved movie frames be appropriate under imagery licensing?
- Should movie mode use a physically raised surface and true 3D raft/character with interaction physics?
- Should we store time-indexed water grids so route replay shows matching historical water conditions?

- After visual and performance comparison, should GPU Studio become the default homepage?
- What shared scenario schema and DEM vertical datum would allow round-trip import/export?
- Which published benchmark terrain and measured flood events will validate Studio and Classic predictions?
- Should the combined Python server implement a restricted and cached proxy for approved imagery/elevation hosts?
- Should movie playback rewind the water surface in sync with the raft trajectory and allow video exports?
